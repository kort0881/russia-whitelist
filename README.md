## Что такое белые списки и как они устроены

Когда в регионе ограничивают мобильный интернет, оператор не выключает сеть целиком — он включает фильтр,
который пропускает только разрешённые направления. Разрешённым считается трафик, у которого совпадает одно
из условий, а в новых конфигурациях — оба сразу:

| Проверка | Что смотрит оператор | Что это значит для вашего сервера |
|---|---|---|
| SNI / домен | имя домена в TLS-хендшейке | домен должен быть из списка разрешённых |
| IP / подсеть | адрес назначения | IP сервера должен лежать в разрешённой подсети |

Три режима, которые встречаются на практике:

1. **Только SNI.** Оператор смотрит имя домена, IP не важен. Достаточно подставить «разрешённый» SNI —
   это самый простой и самый недолговечный вариант.
2. **Только IP.** Разрешены подсети из списка (госуслуги, банки, маркетплейсы, часть CDN и облаков),
   домен не проверяется. Нужен сервер, чей IP попадает в разрешённую подсеть.
3. **IP + SNI одновременно.** Ломает оба предыдущих приёма по отдельности. Требует связки: разрешённый IP
   и разрешённое имя. Именно сюда операторы двигаются с 2026 года.

Дополнительно: часть ограничений — не фильтр, а троттлинг (трафик идёт, но на 10–20 Кбит/с), а в отдельных
регионах — полное отключение, при котором не работает ничего, кроме нескольких госсайтов. В последнем случае
белый список не поможет: канала физически нет.

Списки различаются по оператору, региону, вышке и даже по виртуальному оператору (MVNO): Yota на сети Мегафона
может иметь другой набор разрешённых адресов, чем сам Мегафон в той же точке. Единого «правильного» списка
не существует — существует пересечение, собранное сообществом.

## Как за две минуты понять, что вы под белым списком

Откройте браузер на мобильном интернете и проверьте по порядку:

| Что проверить | Результат | Вывод |
|---|---|---|
| `yandex.ru`, `gosuslugi.ru` | открываются | канал есть, фильтр работает |
| `2ip.ru`, `yahoo.com` | таймаут или сброс | вас ограничили по списку |
| `ping 1.1.1.1` | не отвечает | ICMP тоже режется — обычное дело при вайтлистинге |
| скорость на разрешённом сайте | 10–20 Кбит/с | не блокировка, а троттлинг |
| не открывается ничего, включая госуслуги | полный блэкаут | белый список бессилен, нужен другой канал связи |

Точный ответ даёт не «на глаз», а сверка с данными операторов:

```bash
# проверка IP или домена по актуальным спискам (Python 3.8+, без зависимостей)
python3 tools/wlcheck.py --ip 203.0.113.10
python3 tools/wlcheck.py --domain example.com
python3 tools/wlcheck.py --domain example.com --json
```

Скрипт скачивает публичные списки, проверяет вхождение адреса в подсети и сверяет домен со списком SNI.
Подробнее — [`guides/check-whitelist.md`](./guides/check-whitelist.md).

## Данные: домены, IP и подсети

Три формата — под разные задачи:

| Формат | Файл | Для чего |
|---|---|---|
| домены и SNI | [`whitelist.txt`](./whitelist.txt) | подстановка SNI в VLESS/Trojan, проверка домена |
| подсети в CIDR | [`data/upstream/cidrwhitelist.txt`](./data/upstream) | выбор хостинга, проверка IP сервера |
| отдельные адреса | [`data/upstream/ipwhitelist.txt`](./data/upstream) | точечная сверка, когда CIDR слишком грубый |

Порядок величин в объединённом наборе: **≈30 000 подсетей**, **≈140 000 отдельных адресов**, **≈900 доменов**.
Точные цифры и дата снимка — в шапке каждого файла.

**Важно про свежесть.** Списки — снимок, а не константа: оператор меняет их без объявлений, обычно в сторону
сужения. Если ваша подсеть «была белой» неделю назад — перепроверьте, а не полагайтесь на память.

## Три схемы, которые работают, и их пределы

| Схема | Что обходит | Сложность | Когда ломается |
|---|---|---|---|
| **1. SNI-спуфинг** — сервер за рубежом, в клиенте подставлен разрешённый SNI | проверку по домену | низкая | оператор начал проверять IP |
| **2. «Белый» хостинг** — сервер с IP из разрешённой подсети: RU-CDN, облако, хостинг с российскими диапазонами | проверку по IP | средняя | выдали «серый» IP из соседнего диапазона |
| **3. Двухзвенный релей** — клиент → хоп с «белым» IP → зарубежный выход (Reality) | и IP, и SNI | высокая | хоп потерял «белый» IP или упал |

Практика 2026: схема 1 работает всё реже, схема 2 зависит от того, какой адрес вам реально выдадут,
схема 3 — самая устойчивая, но требует двух серверов и обслуживания. Разборы по шагам:

- [`guides/whitelisted-hosting.md`](./guides/whitelisted-hosting.md) — как найти и проверить «белый» хостинг;
- [`guides/two-hop-relay.md`](./guides/two-hop-relay.md) — сборка двухзвенного релея;
- [`guides/vps-reality-setup.md`](./guides/vps-reality-setup.md) — базовый сервер Reality с нуля.

## Cloudflare и другие ставки, которые не срабатывают

Самая частая ошибка — «повешу домен на Cloudflare, он же популярный CDN, значит пройдёт».
Проверка показывает обратное: в списках российских операторов **Cloudflare почти отсутствует** — на объединённом
наборе совпадает единственная подсеть (`141.101.183.0/24`), и то не у всех операторов. Во время ограничений
домен за Cloudflare просто не откроется.

Что действительно встречается в списках: российские CDN и облака (Edgecenter, DDoS-Guard, сегменты «cdn»),
подсети крупных российских сервисов, часть магистральных сетей. Отсюда вывод: мост под белые списки вешают
на **разрешённый** CDN или RU-облако, а не на самый популярный.

Отдельный миф — «GitHub доступен, сделаю канал через него». Диапазоны GitHub в белых списках не значатся,
а использование CI/CD как прокси нарушает условия сервиса. Как бесплатный CI для проверок — да;
как канал доступа — нет.

## Частые ошибки и мифы

| Миф | Как на самом деле |
|---|---|
| «Достаточно подставить чужой SNI» | работает, только пока оператор не проверяет IP; в режиме IP+SNI бесполезно |
| «Cloudflare в белом списке, потому что он везде» | почти нет; проверяйте по CIDR, а не по репутации |
| «Domain fronting спасёт» | CDN давно терминирует TLS по SNI, подмена хоста ломает соединение |
| «Wi-Fi спасёт» | если трафик уходит через мобильный шлюз, ограничение остаётся |
| «Возьму VPS в РФ — и всё» | IP из РФ часто в серых диапазонах; нужен конкретно «белый» диапазон |
| «Один раз настроил — работает всегда» | списки меняются; нужна проверка по расписанию |
| «Белый список = блокировка» | часто это троттлинг на 10–20 Кбит/с, а не сброс |

Полный разбор — [`guides/myths.md`](./guides/myths.md).

## FAQ — частые вопросы

**Что такое белые списки простыми словами?**
Список ресурсов, к которым оператор мобильной связи пропускает трафик при ограничениях. Всё, чего в списке нет,
не открывается: соединение либо сбрасывается, либо уходит в таймаут.

**Как понять, что мобильный интернет работает по белому списку?**
Яндекс и Госуслуги открываются, а `2ip.ru`, `yahoo.com` и `ping 1.1.1.1` — нет. Это классический признак.

**Поможет ли обычный VPN?**
Обычный VPN подключается к адресу, которого в списке нет, — он не откроется. Нужен либо разрешённый SNI,
либо сервер в разрешённой подсети, либо двухзвенный релей.

**Cloudflare обходит белые списки?**
Практически нет: его подсети в списках российских операторов почти не встречаются. Ставка на CF не работает
в режиме ограничений.

**Какой хостинг брать?**
Тот, чей IP попадает в CIDR из `data/upstream/cidrwhitelist.txt`. Проверяйте конкретный выданный адрес,
а не обещания провайдера: соседний диапазон того же провайдера может быть уже закрыт.

**Работает ли SNI-спуфинг в 2026 году?**
Только у операторов, которые ещё проверяют лишь домен. Там, где включена проверка IP+SNI, — нет.

**Что делать, если не работает ничего, даже Госуслуги?**
Это полный блэкаут, а не белый список. Канал физически отключён; нужен другой способ связи — проводной интернет,
спутник, другой оператор в зоне покрытия.

**Почему списки у всех разные?**
Фильтр настраивается по региону, оператору, вышке и MVNO. Наборы различаются; в репозитории — пересечение,
собранное сообществом, а не «официальный» перечень.

**Как часто обновляются данные?**
Подсети и IP — автоматически (см. `.github/workflows/`), доменный список — через pull request.
Дата снимка указана в шапке каждого файла.

**Можно ли использовать эти данные для проверки своей сети?**
Да, для диагностики и планирования сети это обычная справочная информация.

**Как предложить правку?**
Pull request в `whitelist.txt` или в `data/`, либо тема в [Discussions](https://github.com/kort0881/russia-whitelist/discussions).

**Репозиторий связан с каким-то сервисом?**
Нет. Это справочные данные, инструменты и гайды. Канал автора — в [`INFO.md`](./INFO.md).

## English summary

**Russia mobile internet whitelist (2026).** When mobile internet is restricted in Russia, operators keep only
whitelisted domains and IP ranges reachable. This repository collects those lists (≈30k CIDR subnets, ≈900 SNI
domains), ships a checker (`tools/wlcheck.py`), and documents which access schemes still work: SNI spoofing
(only where the operator checks SNI alone), hosting inside a whitelisted subnet, and a two-hop relay
(client → whitelisted hop → foreign Reality exit). Cloudflare is effectively **not** present in operator
whitelists. Docs: [`guides/`](./guides) · Machine-readable summary: [`llms.txt`](./llms.txt) ·
Data: [`whitelist.txt`](./whitelist.txt), [`data/upstream/`](./data/upstream).
