# Данные: откуда берутся и как обновляются

Каталог `data/upstream/` наполняется автоматически workflow `.github/workflows/data-refresh.yml`
(ежедневно, а также по кнопке `workflow_dispatch`).

| Файл | Что внутри | Источник |
|---|---|---|
| `cidrwhitelist.txt` | подсети операторов в CIDR-нотации | [hxehex/russia-mobile-internet-whitelist](https://github.com/hxehex/russia-mobile-internet-whitelist), MIT |
| `ipwhitelist.txt` | отдельные разрешённые адреса, по одному на строку | там же |
| `whitelist-domains-upstream.txt` | домены (SNI) из списков сообщества | там же |

Доменный список самого репозитория — [`../whitelist.txt`](../whitelist.txt): он курируется вручную
(через pull request), потому что домены требуют проверки на живых сетях.

## Правила

- В каждом файле сверху — шапка с источником, лицензией, датой снимка и коммитом источника.
- Если источник недоступен, workflow не затирает старые данные: файлы остаются как есть, работа отмечается как failed.
- Данные не содержат персональных данных: только домены, подсети и адреса.
- Использование третьих сторон — по их лицензии (MIT) и с указанием источника в шапке.

## Как пользоваться локально

```bash
python3 tools/wlcheck.py --ip 203.0.113.10          # проверит по кэшу (12 часов)
python3 tools/wlcheck.py --domain example.com --refresh
```

Скрипт тянет данные из этого репозитория, а при недоступности — из источника напрямую.
