# Как проверить домен и IP по белым спискам операторов

Проверка нужна в трёх случаях: понять, ограничили вас или нет; выбрать сервер, который пройдёт; и убедиться,
что «рабочий» конфиг не сломался после очередного изменения списков.

## 1. Быстрая проверка без инструментов

На мобильном интернете:

| Проверка | Команда / действие | Что означает |
|---|---|---|
| госсайты | открыть `gosuslugi.ru` | если открывается — канал жив, фильтр работает |
| внешний адрес | открыть `2ip.ru` | если таймаут — вас ограничили |
| ICMP | `ping 1.1.1.1` | при вайтлистинге ICMP обычно режется |
| чужой домен | открыть любой неэпопулярный сайт | таймаут или сброс — фильтр по списку |

Если не открывается **ничего**, включая Госуслуги, — это не белый список, а полное отключение: проверять списки
бессмысленно, канала нет.

## 2. Проверка IP по подсетям

```bash
python3 tools/wlcheck.py --ip 203.0.113.10
```

Что делает скрипт:

1. скачивает публичные списки (`cidrwhitelist.txt`, `ipwhitelist.txt`) и кэширует их на 12 часов;
2. проверяет, входит ли адрес в какую-либо подсеть;
3. печатает результат и, с `--json`, машиночитаемый ответ.

Пример вывода:

```
IP 203.0.113.10
  подсети: 30228 проверено
  результат: НЕ найден в белом списке
```

Проверять нужно **тот адрес, который реально выдан серверу** (`curl -4 ifconfig.me` на самом сервере), а не тот,
что обещает хостинг в описании тарифа: соседний диапазон того же провайдера может быть уже закрыт.

## 3. Проверка домена (SNI)

```bash
python3 tools/wlcheck.py --domain example.com
```

Скрипт ищет точное совпадение и родительские домены (`example.com` засчитывается, если в списке есть
`sub.example.com`, но не наоборот). Отдельно смотрите, что домен вообще отдаёт TLS на 443 и что сертификат
соответствует имени — иначе проверка «в списке» ничего не даст.

## 4. Проверка «в бою»: подстановка SNI

Самый честный тест — попробовать подключиться в режиме ограничений и посмотреть, где рвётся:

| Симптом | Где проблема |
|---|---|
| TCP-соединение не устанавливается | режется по IP (или хост недоступен) |
| TCP есть, TLS-хендшейк обрывается | режется по SNI |
| TLS проходит, данные идут на 10–20 Кбит/с | троттлинг, а не блокировка |
| проходит по SNI, но не проходит по IP | включён режим IP+SNI |

Диагностика на сервере: `journalctl -u xray -n 50 --no-pager`, на клиенте — логи приложения.
Отсутствие записей в логах сервера при неудачном подключении означает, что до сервера просто не дошли.

## 5. Как часто проверять

- при выборе хостинга — до оплаты;
- после выдачи IP — сразу, до настройки;
- далее по расписанию (раз в сутки достаточно), потому что списки сужаются без объявлений.

Автоматизация: `.github/workflows/data-refresh.yml` обновляет данные в репозитории ежедневно, а проверку
своего адреса удобно повесить в cron на любом сервере:

```bash
0 6 * * * cd /opt/russia-whitelist && python3 tools/wlcheck.py --ip $(curl -4 -s ifconfig.me) --json \
  >> /var/log/wlcheck.log 2>&1
```

## 6. Чего проверка не показывает

- **Регион и оператора.** Списки различаются по регионам, вышкам и MVNO. Совпадение по объединённому набору
  не гарантирует проход у конкретного оператора.
- **Троттлинг.** Адрес может быть разрешён, но скорость урезана.
- **Будущее.** Снимок актуален на дату в шапке файла, не дальше.
