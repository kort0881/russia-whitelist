# Что не работает и почему: разбор с проверками

Ниже — приёмы, которые продолжают советовать в сети, и причины, по которым они не дают результата в режиме
белых списков. Для каждого пункта указано, как проверить самому, а не верить на слово.

## 1. «Подставлю чужой SNI — и всё»

**Что обещают:** если в клиенте указать `sni=yandex.ru`, оператор пропустит трафик.

**Что происходит:** работает только у операторов, которые проверяют **лишь** имя домена. Там, где включена
проверка адреса назначения (модель IP + SNI), соединение рвётся независимо от SNI.

**Проверка:** [`check-whitelist.md`](./check-whitelist.md) — сверьте IP сервера с подсетями. Если IP не в списке,
SNI-спуфинг не поможет.

## 2. «Cloudflare пройдёт, он же везде»

**Что обещают:** домен за Cloudflare доступен всегда, потому что CF — популярный CDN.

**Что происходит:** в объединённом наборе списков операторов совпадает единственная подсеть CF
(`141.101.183.0/24`), и то не у всех операторов. В режиме ограничений домен за CF не открывается.

**Проверка:** `python3 tools/wlcheck.py --ip <IP вашего домена за CF>`.

## 3. «Domain fronting спасёт»

**Что обещают:** можно ходить через чужой домен, подменяя заголовок Host.

**Что происходит:** CDN терминирует TLS по SNI и отклоняет запрос, если хост не совпадает с SNI. Как рабочий
приём это перестало существовать несколько лет назад. Плюс механизм дополнительно ломает сертификаты.

**Проверка:** попробуйте запрос с несовпадающими SNI и Host — получите ошибку или 421.

## 4. «Сделаю канал через GitHub»

**Что обещают:** GitHub доступен, значит через Actions/raw можно гонять трафик.

**Что происходит:** диапазоны GitHub в белых списках не значатся, а использование CI/CD как прокси нарушает
условия сервиса — аккаунт блокируют. Как бесплатный CI для проверок — да, как канал доступа — нет.

**Проверка:** `python3 tools/wlcheck.py --ip <адрес github.com>`.

## 5. «Wi-Fi всегда спасёт»

**Что обещают:** на Wi-Fi ограничения не действуют.

**Что происходит:** если Wi-Fi-сеть выходит в интернет через мобильный шлюз (раздача с телефона, модем,
корпоративная сеть с мобильным аплинком) — ограничение остаётся. Работает только другой аплинк:
проводной провайдер, спутник.

## 6. «Возьму VPS в РФ — и проблема решена»

**Что происходит:** российский IP сам по себе ничего не даёт: нужен адрес именно из разрешённой подсети.
Диапазоны хостингов часто «серые» даже внутри РФ.

**Проверка:** сверка выданного IP по CIDR до оплаты годового тарифа.

## 7. «Один раз настроил — работает всегда»

**Что происходит:** списки меняются без объявлений, обычно в сторону сужения; меняются и режимы (SNI → IP → IP+SNI).
Конфиг, который работал месяц назад, может не работать сегодня.

**Что делать:** ежедневная проверка по расписанию плюс резервный канал.

## 8. «Белый список = полная блокировка»

**Что происходит:** чаще это троттлинг: соединение устанавливается, но скорость 10–20 Кбит/с. Диагностически
это разные вещи — при троттлинге трафик идёт, и часть протоколов остаётся работоспособной на малых объёмах.

## 9. «IPv6 обойдёт ограничения»

**Что происходит:** у операторов IPv6 либо отсутствует, либо ограничен так же. Механизм не проверен и
не может считаться рабочим вариантом.

## 10. «Скрипт из случайного репозитория всё настроит»

**Что происходит:** вы запускаете от root чужой код, который может измениться в любой момент — в том числе
на вредоносный. Ставьте ядро официальным установщиком, конфиг собирайте сами, проверяйте `xray -test`.

---

**Общее правило:** любое утверждение проверяется двумя фактами — входит ли адрес в список и не режется ли
имя домена. Всё остальное — рассказы.
